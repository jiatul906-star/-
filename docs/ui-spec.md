# UI 规格

> 状态：起草中 | 最后更新：2026-05-15

## 核心理念

角色和窗口**分离但关联**——关闭窗口角色不消失，退回桌面。角色始终在线，是一个"伴侣"而非软件装饰。

---

## 整体风格

- 浅色为主，窗口圆润，参考 QQ 面板布局
- 字体：微软雅黑（`"Microsoft YaHei", "Segoe UI", system-ui, sans-serif`）
- 面板风格参考 QQ（左侧竖排头像栏 + 右侧内容区）

---

## 三级菜单结构

### Level 1 — 桌宠模式（桌面流浪）

- 角色独立悬浮桌面，无窗口
- 角色自由走动/待机，可拖拽到任意位置
- **左键**：互动菜单（具体条目待定）
- **右键**：弹出对话气泡（漫画风，从角色嘴边引出，无历史记录，自动消失）
- **拖拽**：播放"被抓起来"的动作帧，放下切回站立/坐下

### Level 2 — 聊天模式

参考 QQ 面板：左侧竖排头像栏 + 右侧聊天区。

```
    ┌────────────────────────────┐
    │     角色骑在顶栏边框       │
    ├────┬───────────────────────┤
    │ ○  │  角色A                │  ← 顶栏：小头像 + 名字
    │ ○  ├───────────────────────┤
    │ ○  │                      │
    │ ○  │  聊天消息区           │
    │ ○  │  AI气泡 / 用户气泡     │
    │ ○  │                      │
    │ ○  │                      │
    │ +  ├───────────────────────┤
    │    │  输入框         [发送] │
    └────┴───────────────────────┘
       ↑
      左侧角色列表（竖排圆形头像）
      选中态高亮
```

- **左侧角色栏**：竖排圆形头像列表，可切换角色。是否可收起——待定。
- 窗口圆润，偏窄，适合常驻桌面
- 移动窗口 → 角色跟着走
- 拖拽角色离开窗口 → 回到 Level 1
- 把角色扔到窗口顶部 → 自动坐回去
- 流式逐字输出，末尾有呼吸光标

**显示密度**：用户可选择两种模式

| 模式 | 正文 | 行高 | 气泡间距 |
|------|------|------|---------|
| 舒适 | 15px | 1.6 | 12px |
| 紧凑 | 14px | 1.5 | 8px |

### Level 3 — 设置模式

- 独立设置窗口
- 角色可以骑在设置窗口边框上
- 左侧角色切换，右侧设置面板

```
┌──────────────────────────────────────┐
│  设置                          [✕]   │
├─────────────┬────────────────────────┤
│  角色列表    │  当前角色编辑           │
│             │  外观 / 性格 / 声音     │
│  ○ 角色A    │                        │
│  ○ 角色B    │  AI 设置               │
│  ○ 角色C    │  API地址 / Key / 模型  │
│  + 新建     │                        │
│             │  界面布局设置           │
│  ────────  │                        │
│  外观/关于  │                        │
└─────────────┴────────────────────────┘
```

---

## 窗口与角色关联规则

| 状态 | 窗口 | 角色位置 |
|------|------|---------|
| Level 1 | 无窗口 | 桌面任意位置，可拖拽 |
| Level 2 | 聊天窗口 | 骑在窗口顶栏边框 |
| Level 3 | 设置窗口 | 骑在设置窗口顶栏/角落 |

---

## 对话气泡设计（Level 1 右键）

- 漫画风格，从角色嘴边引出
- 无历史记录功能
- 短暂显示后自动消失
- 不是矩形输入框，是纯展示气泡

---

## 设计原则

1. **递进式复杂度**：Level 1 最简，Level 3 功能最全
2. **角色不挡内容**：角色坐在边框上，不占窗口内部空间
3. **始终陪伴**：关闭窗口不等于关闭角色
4. **窗口小巧**：不做大而全的面板，适合长期驻留桌面

## UI 设计难点与细节处理

### 1. Level 2 → 3 过渡方式不明确

当前设计 Level 3 是独立窗口。如果聊天窗口 + 设置窗口同时存在，桌面上会有：
- 桌宠（独立）
- 聊天窗口
- 设置窗口

三个东西。用户会困惑：哪个是主窗口？关闭设置窗口后聊天窗口还在不在？

**需要决策**：设置是替换聊天窗口内容区，还是独立弹窗？如果独立，聊天窗口是否收起？

---

### 2. 单角色时左侧栏闲置

Level 2 左侧竖排头像栏参考 QQ，但 QQ 有几十个好友，而本产品大部分用户可能只创建 1 个角色。此时左侧栏只有一个头像 + 一个"+"号，占用宽度但无信息量。

**需要决策**：左侧栏是否在单角色时自动隐藏？还是始终显示但缩小宽度？

---

### 3. TTS 播放缺视觉反馈

TTS 是差异化功能，但当前设计没有定义语音播放时的 UI 状态：

- 角色嘴型同步怎么做？（素材是否支持？）
- AI 气泡正在播放语音时，有没有声波/音轨指示？
- 播放中用户又发了一条消息，是打断还是排队？
- 流式播放加载失败时的反馈？

**需要决策**：TTS 播放态至少需要气泡上的声波指示器 + 角色一个"说话中"状态。

---

### 4. 空状态——初始启动无角色

用户首次打开软件，没有创建任何角色时：

- 桌宠显示什么？默认形象？还是引导页？
- Level 2 聊天窗口里角色名显示什么？
- 是否应该有一个快速向导，引导用户创建第一个角色？

**需要决策**：首次启动时的默认状态和引导流程。

---

### 5. 加载与错误状态

| 场景 | 当前设计 | 需要补充 |
|------|---------|---------|
| AI 请求发送中 | 未定义 | 气泡内 loading 动效（三个点？角色思考表情？） |
| AI 请求超时 | 未定义 | 错误提示样式 + 重试按钮 |
| 网络断开 | 未定义 | 全局/局部掉线提示 |
| TTS 语音生成失败 | 未定义 | 降级为纯文字，还是显示错误图标？ |
| API Key 未配置/失效 | 未定义 | 引导提示，至少告知用户去哪设置 |

这些事情提前定义好，出来的东西才有整体感，不会被看出来是"拼凑的"。

---

### 6. 桌宠生命周期——窗口操作时的行为

| 用户操作 | 桌宠？ | 聊天窗口？ | 当前设计 |
|---------|--------|-----------|---------|
| 关闭聊天窗口 | 还在吗？ | — | ❓ |
| 最小化聊天窗口 | 还在吗？ | 收到任务栏 | ❓ |
| 点任务栏恢复窗口 | 自动坐回去？ | 恢复 | ❓ |
| 拖拽聊天窗口 | 跟着走 | 移动 | 已定义：跟着走 |
| 多显示器 | 角色在哪？ | 在哪？ | ❓ |
| 聊天窗口最大化 | 角色坐哪？ | 全屏 | ❓（窗口最大化时边框可能被遮挡） |

**建议**：不管窗口开闭，桌宠始终存在。关闭/最小化窗口 = 角色从边框跳下来，回到桌面自由态。

---

### 7. 右键对话气泡——技术边界

Level 1 右键弹出漫画风气泡，有几个细节：

- 气泡随角色移动吗？（如果用户拖拽角色，气泡是否跟随？）
- 如果连续右键，是替换旧气泡还是堆叠？
- 气泡朝向：始终朝左？还是根据角色在屏幕上的位置动态调整？（角色靠右时气泡朝右）

**需要决策**：气泡跟随角色 → 是；新气泡替换旧气泡 → 是；气泡方向 → 动态调整。

---

### 8. 桌宠 z-order

桌宠窗口需要始终置顶（TopMost），但如果用户在看视频/打游戏：

- 始终置顶会很烦人
- 不置顶会被其他窗口挡住，失去"陪伴"感

**需要决策**：右键菜单里是否加"暂时隐藏/收进托盘"选项？或者检测全屏应用时自动降低到正常层级？
