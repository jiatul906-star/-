# 架构方案分析

> 状态：方案已确定（C）| 最后更新：2026-05-15

## 背景

AI 聊天工具包含五个功能模块：AI 聊天、DIY 角色创建、TTS 语音、桌宠、多角色管理。需要确定它们之间的组织方式。

## 三种方案

### 方案 A：独立模块 —— 各自独立程序

每个功能是独立小程序，共享一份数据。

```
┌─ 聊天窗口 ─┐    ┌─ 桌宠 ─┐    ┌─ DIY编辑器 ─┐
│   AI对话    │    │  动画   │    │  角色配置    │
│   TTS播放   │    │  交互   │    │  图片上传    │
└─────────────┘    └────────┘    └──────────────┘
       ↕                ↕               ↕
  ┌─────────────────────────────────────────┐
  │              共享数据层                   │
  │         (角色配置、聊天记录)               │
  └─────────────────────────────────────────┘
```

| 优点 | 缺点 |
|------|------|
| 模块独立，一个崩了不影响其他 | 整体感差，用户感觉是"几个软件" |
| 可分别开发、分别更新 | 模块间通信复杂，数据同步易出错 |
| 桌宠可独立悬浮 | 安装包可能是多个，体验割裂 |

### 方案 B：大一统单体 —— 所有功能在一个窗口

```
┌──────────────────────────────┐
│         主窗口                 │
│  ┌─ 标签栏 ─────────────────┐ │
│  │ 聊天 │ DIY │ 设置 │ ...  │ │
│  ├──────────────────────────┤ │
│  │                          │ │
│  │   当前功能区域             │ │
│  │                          │ │
│  ├──────────────────────────┤ │
│  │   底部状态栏（桌宠小窗）    │ │
│  └──────────────────────────┘ │
└──────────────────────────────┘
```

| 优点 | 缺点 |
|------|------|
| 整体感强，体验统一 | 代码耦合，改一处可能影响全局 |
| 开发简单，数据共享容易 | 越来越臃肿，维护成本递增 |
| 一个安装包搞定 | 桌宠局限在窗口内，无法悬浮桌面 |

### 方案 C：壳 + 插件 —— 主程序 + 独立模块插件

轻量主程序（壳），每个功能是插件，可独立窗口也可嵌入。

```
┌──────────────────────┐
│      主程序（壳）      │
│  ┌──────────────────┐│
│  │ 插件系统          ││
│  │ ├ 聊天插件        ││
│  │ ├ DIY插件         ││
│  │ ├ TTS插件         ││
│  │ └ 桌宠插件 ← 可弹出独立窗口 ││
│  └──────────────────┘│
│                      │
│  共享：UI主题/数据/AI │
└──────────────────────┘
```

| 优点 | 缺点 |
|------|------|
| 整体感 + 模块独立性兼得 | 前期搭框架需要时间 |
| 桌宠可弹出桌面，也可嵌在主窗口 | 对架构设计能力有要求 |
| 后续加新功能不伤筋骨 | |

---

## Claude 的推荐：方案 C

理由：

1. **桌宠天生需要独立窗口** — 必须能从主窗口弹出，A 能做到但体验割裂，B 做不到
2. **DIY 是核心竞争力** — 以后大概率有新想法，插件架构加功能不用重写
3. **上次崩盘就是因为架构缺乏约束** — 插件系统本身就是约束，逼着每个模块按规矩来

代价：搭框架多花一周左右。收益：后面加功能成本大幅降低。

### 问题 1：插件框架方案

插件之间怎么隔离和加载？

| 选项 | 说明 | 适用场景 |
|------|------|---------|
| 简单模块加载 | 编译时或动态 import，共享进程 | 小项目，插件间信任度高 |
| 微前端 (qiankun/Micro-app) | 各插件独立构建，运行时加载 | Web 技术栈，需要独立部署 |
| 进程隔离 (Electron BrowserWindow/WebContents) | 每个插件独立进程 | 安全性高，插件可能来自第三方 |

你的推荐是？还是有其他方案？

### 问题 2：桌宠桌面悬浮实现

桌宠需要"可以嵌入主窗口，也可以弹出独立悬浮在桌面"。具体怎么实现？

| 选项 | 说明 |
|------|------|
| Electron BrowserWindow (alwaysOnTop + transparent) | 独立窗口，置顶透明，可拖拽 |
| Electron 多窗口 + 主窗口通信 | 主窗口和桌宠窗口 IPC 通信同步状态 |
| 其他方案 | 你判断 |

需要你确认技术可行性和具体选型。
