## 三、开发阶段

### P0：骨架（预计 3-5 天）

**目标**：窗口能跑、主题能切、布局正确。

```
□ 主窗口框架（frameless + 自绘标题栏 + 圆角窗口）
□ CSS 变量主题系统（5 主题 × 2 明暗 + 切换动画）
□ 组件树搭建（TitleBar / Sidebar / ChatArea / InputBar / SettingsOverlay）
□ 窗口尺寸控制（默认 420×600、最小 320×360、可拖拽调大小）
□ 左侧栏逻辑（单角色 22px / 多角色 52px）
□ 桌宠透明窗口（BrowserWindow transparent + alwaysOnTop）
□ 桌宠 idle 动画循环
□ 主窗口 ↔ 桌宠窗口 IPC 通道
```

**验收标准**：
- 启动 → 看到主窗口 + 桌宠
- 拖拽窗口边角 → 尺寸变化，布局不崩
- 切换主题 → 色板 + 明暗生效
- 桌宠在桌面显示，可拖拽

---

### P1：聊天核心（预计 5-7 天）

**目标**：能对话、能看历史。

```
□ 气泡组件（AI/用户两变体，圆角 + 阴影 + 最大宽度 75%）
□ 流式逐字输出 + 呼吸光标
□ 消息列表（滚动 + 自动滚到底）
□ 输入框 + 发送按钮
□ AI API 对接（通过设置的 API 地址/Key）
□ 聊天历史本地存储
□ Level 2 角色切换（左侧栏 + 桌宠跟变）
□ Level 1 ↔ Level 2 过渡（双击桌宠→开聊天窗口→角色跳上边框）
□ 桌宠 sit_on_window / jump_off 动作
□ Level 1 戳角色（随机反应动画 + 台词）
□ Level 1 右键气泡（堆叠飘动 + 动态朝向）
```

**验收标准**：
- 输入消息 → AI 逐字回复 → 气泡正确显示
- 戳桌宠 → 有动画+台词
- 右键桌宠 → 堆叠气泡
- 双击桌宠 → 跳到聊天窗口顶栏坐下
- 关窗 → 桌宠跳回桌面

---

### P2：桌宠完整态（预计 3-4 天）

**目标**：桌宠有灵魂，不只是图片。

```
□ 完整动画状态机（idle/walk/blink/talk/react/grabbed/jump）
□ 随机 idle 行为（偶尔眨眼、偶尔走动）
□ 拖拽桌宠（grabbed 动画 + 放下切回 idle）
□ 桌宠生命周期完整（关窗/最小化/最大化/恢复）
□ 系统托盘（角色大头照图标 + 右键菜单）
□ 托盘隐藏/显示桌宠
□ Level 1 左键互动菜单（聊天 + 摸头）
□ 摸头交互（反应动画 + 台词）
```

**验收标准**：
- 桌宠偶尔眨眼、走动
- 拖拽桌宠 → 被抓动画 → 放下自由
- 最小化窗口 → 桌宠跳下桌面
- 恢复窗口 → 桌宠跳回
- 最大化 → 桌宠跳下桌面
- 托盘 → 隐藏/显示/退出正常工作

---

### P3：设置 + DIY（预计 4-6 天）

**目标**：用户能创建和编辑自己的角色。

```
□ 设置弹窗（浮层，ChatArea 上方）
□ 左侧分类导航（角色 / AI 设置 / 界面外观）
□ 角色编辑——外观标签（立绘/头像/桌宠图上传 + 裁剪预览）
□ 角色编辑——性格标签（模板标签 + 自由文本）
□ 角色编辑——声音标签（语速/音调/音量滑块 + 试听）
□ 新建角色流程
□ 角色数据持久化（本地 JSON/文件）
□ AI 设置（API 地址/Key/测试连接）
□ 界面外观设置（主题色选择/明暗开关/显示密度）
□ 首次启动角色选择界面（4 官方角色横排卡片 + 确认流程 + 引导模式）
```

**验收标准**：
- 点设置 → 弹窗浮在聊天上方
- 新建角色 → 三种标签自由切 → 保存 → 出现在侧栏
- AI 设置填 Key → 测试连接 → 有反馈
- 首次启动 → 空状态引导正常

---

### P4：打磨（预计 3-5 天）

**目标**：错误处理、动画补齐、细节优化。

```
□ AI 请求发送中（角色 think 表情 + 气泡跳动点）
□ AI 请求超时（底栏红条 + 重试按钮）
□ 网络断开（角色 sad 表情，恢复自动切回）
□ TTS 失败（角色 silent 表情 + 降级纯文字）
□ API Key 未配置/失效（角色反馈 + 弹出设置）
□ 错误恢复后表情自动回 normal
□ 暗色模式下边框/分割线可见性检查
□ 动效参数微调
□ 窗口圆角 + 阴影在所有平台的一致性
□ 所有 preview HTML 中的交互还原到真实 UI
```

---

### P5：TTS（预计 5-7 天）

**目标**：AI 回复能念出来。

> 方案已确定：IndexTTS（B 站开源，零样本语音克隆）。详见 `specs/tts-analysis.md`。

```
□ IndexTTS 模型部署（Python HTTP 服务，Electron 子进程拉起）
□ 4 个角色参考音频嵌入
□ 流式播放（按句分段合成 → 逐段播放）
□ 播放中角色 talk 表情同步
□ 播放中发送新消息 → 打断策略
□ TTS 开关
□ GPU 检测逻辑（无显卡时灰掉 TTS + 提示）
```

## 四、开发流程（每个功能）

```
① 用户说"我要 XXX"
    ↓
② Claude 翻译成 spec（在对应文档里补充）
    ↓
③ 程序员审阅 spec，提出技术约束
    ↓
④ 程序员 + Claude 协作写代码
    Claude 每次写代码前读取 docs/ 中的对应文档
    确保代码符合 architecture.md 和 design-system.md
    ↓
⑤ 用户对着 spec 验收效果（不看代码）
    ↓
⑥ 通过 → 标记完成 / 不通过 → 回到 ②
```

## 七、风险提示

| 风险 | 影响 | 应对 |
|------|------|------|
| 桌宠动画素材进度慢 | P0-P2 阻塞 | 先用捷径方案（静态帧 + flip） |
| TTS 选型纠结 | P5 延期 | 已确定 IndexTTS，风险解除 |
| 用户用集成显卡 | TTS 不可用 | 检测到无 NVIDIA GPU 时灰掉 TTS，降级纯文本 |
| Electron 打包体积大 | 用户体验 | 加上 IndexTTS ~2.3G 模型后首次安装包较大，需提醒用户 |
| 代码连贯性问题 | 重蹈上次崩盘 | Claude 每次写代码前强制读 docs/ |
